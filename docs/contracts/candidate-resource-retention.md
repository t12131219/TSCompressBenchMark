# M1 候选资源观测与暂存留存

此合同供 M0 的 `m1_lossless_candidate_v2` 开发预检使用。
[资源政策](../../configs/profiles/resource_policy_v1.json)及其 schema 与比较、构建等合同一起冻结；
执行前拒绝政策失配，报告只从封存内容复算。它不授予正式资源、统计或阶段资格。

| 项目 | 采集／执行口径 |
|---|---|
| 磁盘水位 | 每个 slot 启动前在实际运行目录调用 `statvfs`；记录设备、可用空间和可用 inode。阈值为 32 MiB + 本 slot 原始逻辑字节 + 明确的帧上限，以及至少 64 个可用 inode。只检查本 slot，不按压缩率预测输出或累加串行 slot 的空间预留。新 v2 计划在首个 verified 终态前额外计入一次闭包的逻辑字节与文件数 + 3 个目录 inode；提交后不重复预估，实测可用空间已反映写入。 |
| 内存水位 | 读取 `/proc/meminfo` 的主机 `MemAvailable`，阈值为 64 MiB + 本 slot 原始逻辑字节。内存和磁盘水位是运行前检查，不是预留、进程硬限或 cgroup 可用量。 |
| 资源阻断 | 水位不足或必要的观测不可得，产生 `resource_blocked` 终态，不启动该 slot 的 worker，不填造时钟或资源用量；串行检查后续 slot 的当时水位。未实现自动检查点续跑。 |
| 实际子进程 | 当 `waitid(..., WNOWAIT)` 通知退出后，按 PID 用 Linux `wait4` 一次回收并记录 user/system CPU 时间与 `ru_maxrss`；崩溃、超时或取消且已实际启动时也按同口径。`ru_maxrss` 仅按 Linux 的子进程回收统计换算字节，不是并发进程组、调用者和页缓存的合计峰值，也不是 codec 独占工作区。 |
| 墙钟及存储 | 进程墙钟仍含启动及回收。另记运行目录创建后至封存文件清单计算完的整体单调墙钟，不以各操作之和代替。统计封存文件数及逻辑字节，不冒充物理占用或峰值。 |
| 暂存处置 | 调解码器前移除临时原始输入副本，不影响冻结语料；副本的清除不计为“验证后回收”。成功时先逐产物验证并落账，封存共享解码依赖后才删除暂存恢复文件，记录已回收数量和逻辑字节。依赖无法完整复制时报告 `unavailable`，保留验证结果和完整帧，并把已验证的暂存恢复文件移入 `retained/<slot_id>/`；没有 verified slot 时不复制闭包。编解码失败时把现存暂存文件移入同一运行的 `failures/<slot_id>/`，封存日志和现有帧，不据失败销毁反例。未正常封存的中断不算完整结果。 |

资源水位、子进程观测和暂存清单加入现有 `observations.jsonl`，处置终态写入原有事件账本，没有另发
分片任务或收据。离线复算比对观察字段是否对应实际启动、根据原读数重算水位决定、核对留存文件身份、
验证日志以及回收清单；不需要读取当前磁盘/内存状态，也不把已回收文件声称为仍可逐字节复审。

本轮仍不提供 cgroup/CPU 亲和或跨作业独占、并发总体 RSS/线程峰值、严格磁盘配额或归档回取。当前内置恢复闭包仅覆盖三个 v2 候选方法；详见 [M1 候选计划合同](m1-lossless-candidate.md#保留帧独立恢复)。水位规则不直接套用于首批大数据或正式研究比较。
