## 解析和身份

- 锁定 `.txt.gz`/`.csv.gz` 的压缩文件大小和 SHA-256。作者许可与原样复制的天气文件也
  按哈希检查。gzip 是资产保存形式，不能计入待比较算法的压缩成绩。
- 电力是分号分隔、逗号小数点；气象、交通和汇率为逗号分隔、点小数。规范化文件严格按列名/列宽、
  ASCII/LF 和 4 KiB 行限额解析；空项、非法数字和非有限值拒绝，不自动补全或裁剪。
  观测的 81 个气象 `-9999` 字面量原样保留，不在导入器里推断 validity 位或替换为零。
  利用这些值构造缺失任务时须另行冻结 mask 和恢复语义。
- v1/v2 的 T 编为 little-endian i64 秒，基于源文件民用日期标签和 `1970-01-01 00:00:00` 坐标原点；
  不赋时区或把它冒称 UTC。原始顺序保留：电力分隔 900 s；气象有 1 次重复标签、
  1 次 6000 s 间隔，其余 600 s；交通的相邻步长均为 3600 s，汇率均为 86400 s。
  不填补间隙、重采样或去重。
- 两条新轴也使用 little-endian i64，但各自绑定原生时间单位、语义和坐标；`read_labeled_tv_window`
  返回带语义的坐标。只支持旧民用秒的 `read_tv_window` 对两条新轴显式拒绝，不做静默转换。
- V 离线规范化为 little-endian binary64，按列连续；哈希包含 T/V 模式、单位、布局、
  行数、各有序列的 SHA-256。每分区单独绑定 canonical ID；不额外保留完整二进制副本。
  `check-corpus --parse` 重做上述校验，而普通计划核验已锁定的文件和结构、不重扫解码。

## 语料画像与缺口

[语料画像政策](../../catalog/capabilities/corpus_features_v2.json) 登记方案 §6.5 的全部覆盖项和
描述性阈值。`bmk corpus-profile` 单次解析规范文件，一边重算并核对每个分区的 canonical ID，
一边采集画像；报告绑定政策、政策 schema、v3 清单和合成 fixture，分开输出真实资产、合成证据及缺口。
按分区计算，不排序、不跨分区补点、不从结果中挑选表现好的窗口。结果只描述语料，不能签发 codec 资格。

- 规则轴要求正步长且一致。大 gap 取 `≥4 × nominal_step`；无名义步长不判断。重复/倒序均保留。
- 近似趋势按同方向相邻差分占比 `≥95%`，零差分计入分母；跳变指示为绝对差分 `≥16 ×` 非零差分中位数。
  稀疏要求数值零占比 `≥90%`。形状指标至少 32 个可用值，且趋势/跳变至少 31 个有限相邻差分。
- 周期指示只在名义步长规则且至少含两周期的分区上按政策指定 lag 计算；正自相关 `≥0.8`，至少 32 个有效配对。
  同轴 Pearson 逐列配对，记录极值对、可评估对数及强/弱对数；`|r|≥0.9` 为强、`|r|≤0.1` 为弱，常量列或不足 32 对不判。
  自相关/跳变是指标，不是周期、噪声或因果证明。
- 仅气象的 `-9999` 在描述性数值统计中被排除，逐列保留计数；不改变 canonical 值或生成运行 validity 位，
  相邻差分不跨过排除值。独立测量使用非计时路径上的 `tsbench` NumPy；不增加 codec 热路径依赖。

| 轴 | 当前实证 | 仍缺 |
|---|---|---|
| 领域 | 传感器、能源、交通、金融、服务器指标、科学计算各一个独立来源簇 | 仅满足领域有资产；不能据此推断域内代表性或方法覆盖 |
| 类型 | 真实 `i64` T、`f64` V、时间语义的混合表；合成所有有/无符号整数位宽、f32、布尔 | 合成资产存在不等于各方法已验证其适用 dtype |
| 结构 | 18 个多变量分区，17 个规则轴、1 个不规则轴；另有合成单变量、不等长的两条轴、矩阵 `[3,5]` 和张量 `[2,3,5]` | 生产布局与恢复能力按方法另验 |
| 数值 | 常数、周期/跳变指示、稀疏；合成整数极值、f32/f64 特殊位、达阈值的趋势、固定种子的伪随机压力输入 | 伪随机用例不作为真实语料的噪声模型 |
| 大小 | 极短合成对象；电力训练分区有 70,175 行可用；[方法补验](first-batch-method-boundaries.md)测了 ALP、Zstandard、Gorilla 的边界三点 | 其余方法、缓存内外和资源档仍缺合同及验证；长分区可用不等于已跑长工作负载 |
| 相关性 | 真实分区具有共享轴，可复核逐分区的强/弱相关对数；合成对象有不等长的不同轴 | 不同轴的实际容器恢复按方法另验 |
| 异常 | 真实重复标签、大 gap；合成负时间戳、NaN/Inf、独立布尔 validity（无效位有有限非零值，另有有效 NaN） | validity 的执行/恢复验证尚未完成；气象字面哨兵不是该证据 |

未绑定到执行或验证合同的原始文件不计入覆盖；23 个文件的清点继续保留。合成证据不填补领域缺口，
原样复制也不等于运行资格或发布声明。

[合成边界清单](../../datasets/fixtures/corpus-boundaries-v1/manifest.json)锁定 17 个小型 NPY 文件。
使用 `python -B datasets/generators/generate_corpus_boundaries.py --out <empty dir>` 重建；已核对
所有字节与生成清单。它与原微型 fixture 并存，不替换历史用例。画像绑定两个清单、新生成器哈希，
按位/形状验证边界资产；对缓存档、块大小和资源拒绝则仍要求具体运行证据，不根据文件大小推断。

## 使用与维护

`conda activate tsbench` 后执行 `./bmk check-corpus --parse`（默认 v3；可指定 `--version 1` 或 `--version 2`）。
`./bmk corpus-profile` 或 `tsbench.api.profile_corpus` 输出可复算的 v3 画像。禁网预检用这条
命令一次完成 v3 规范核验和画像（报告 `corpus_audit` 字段保留核验摘要）。
`./bmk plan` 生成的首批服务草案绑定 [v3 清单](../../datasets/manifests/first-batch-real-v3.json)及画像政策，
但仍不可执行，不等于完整语料、方法用例与资源预算已冻结。M1 候选固定使用
[原 v1 清单](../../datasets/manifests/first-batch-real-v1.json)，不自动引入新数据。

重做已登记的语料时，运行 `python -B tools/import_unique_corpus.py --version 2 --out <empty dir>`，
默认读 `datasets/raw/unique/`，不联网、不需要上游包、不覆盖运行用资产。用输出的清单及文件
与本地冻结资产逐字节对照。`--out` 必须是空目录，不能作为直接覆盖入口。这里的解析器是导入
审计代码，不替代 M3 的生产 parser 或跨格式执行资格。

使用 `python -B tools/import_domain_corpus.py --out <empty dir>` 从已锁定的本地保留字节离线重建
v3 新增的两个 gzip 和 v3 清单。该维护入口在 `tsbench` 内使用 SciPy 读取 NetCDF；正常规划、
画像和执行只读规范语料，不需要读取 NetCDF 或下载来源。
