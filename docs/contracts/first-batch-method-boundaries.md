# 首批方法边界：开发预检 v1

这是 M0 的**定向开发预检**，不是正式资格，也不测性能。沿用[同版 Unique 证据](first-batch-unique-evidence.md)与已有 native 合同，不重跑来源方全量测试。新增用例具体冻结在[方法边界配置](../../configs/suites/m0_method_boundaries_v1/cases.json)，跟随同一套 `bmk native-plan` / `bmk native-run` 的一个探针执行、由同一本账本保留结果，不另开算法运行或分片收据。

| 方法和原生边界 | 输入与比较控制 | `B−1 / B / B+1` 的判定 |
|---|---|---|
| ALP Auto V，`ALN1` 向量 1024 值 | v2 气象测试分区 `air_temperature`，取同一起点的相邻三种前缀；f64、Auto 编码，解码显式 `scalar-unfused` | 1023、1024、1025 都须逐位恢复；独立解析实际发出的 `ALN1` 得到 1、1、2 个向量（其中 raw/coded 分开记），不能把 1024 当资源上限。 |
| Zstandard 批基线，单块 65,536 输入字节 | v2 电力测试分区 `MT_231`，同一前缀，按原 f64 连续字节给 byte codec；不加外部分块 | 8191、8192 个 f64 须逐位恢复；8193 个 f64（65,544 字节）必须由插件返回 `BMK_RESOURCE_LIMIT`（7），不留输出，不截断或回退。 |
| Gorilla TV 批基线，单块 512 行 | v2 交通测试分区 `channel_0`，同一前缀；civil 秒坐标乘 1000 并按 i64 毫秒编码，V 为 f64 | 511、512 行须同时逐位恢复 T/V；513 行必须由插件返回 7 且无输出。这不是流入口的状态容量结论。 |

另外把[合成边界包](../../datasets/fixtures/corpus-boundaries-v1/manifest.json)中 **9 个 f32 特殊位字**送入 ALP Auto；负零、次正规数、正负无穷及两个不同 NaN payload 都按输入字逐位验证。该用例不外推到其他方法或其他合成 dtype。为了能注入合法的、恰超 Zstd 方法上限的输入，开发探针有单独的 8193 行有界读取入口；既有 M1 普通/训练绑定仍限制在 8192 且不会改用该入口。

同一探针还取 [v3](first-batch-real-corpus.md) 两个新增领域的留出样本：Westermo `cpu-user` 1025 个值和 CEDA `ACCESS-CM2` 57 个值。两列分别由 ALP Auto 与 Zstd 批路线逐位恢复，**只编码 V**，不把两种非民用时间坐标转换为 UTC 或输入 T codec。整个探针共 14 例：12 个成功帧、2 个预期资源拒绝。

## 验证、计费及留存

- 每个成功编码均启动另一个 worker 解码；启动前删除暂存 T/V 和 schema，子进程路径只传帧和输出，不传原输入。不宣称用 OS 禁止读取整个工程语料。
- 每次核对输出 dtype、元素数、原位模式和 schema；编码和解码信息均要求单线程。预期拒绝也必须提供实际状态与无输出证据；它不是成功压缩样本。
- 批任务只核整对象恢复，不报价点/范围或流延时。131,072 字节为这个开发用例的完整序列化帧上限（含封装、schema 和算法 payload），不是 allocator/RSS 上限或协议容量推断。记录实际输入及完整帧字节，不做正式压缩率比较。
- 每个成功样本保留帧、哈希、用例及构建绑定；统一预检将这些帧列为必需二进制证据，缺失或为空不记通过，复算检查计划、账本及封存文件。保留的拒绝是诊断及输入引用，不伪造帧。其他方法的块边界、缓存档、质量和访问预算仍逐组补齐。
