# 比较合同 v1：R/O 任务、资源、流式协议与准入

[比较合同 schema](../../schemas/comparison-contract.schema.json) 把**可比条件**与**方法身份**分开。CLI
`bmk comparison-plan --config <工程内 JSON>` 和 Python `tsbench.api.plan_comparison(root, relative_path)`
共用冻结逻辑，返回合同、schema ID 和 `comparison_id`。冻结不会执行算法，也不会验证用户提供的其他 ID
所引用的外部事实。正式计划生成器须先解析这些 ID 对应的内容；不得用两个相同的用户标签冒充已核验合同。可用本轮
[真实候选解码合同示例](../../results/m0-comparison-contract-20261119-r1/comparison-example-alpn-vector-tail-decode.json)
运行 `comparison-plan`，其 ID 与封存报告中的同一方向一致。

| 比较键 | 冻结条件 |
|---|---|
| 原始对象与恢复任务 | canonical 输入及分区、原始 schema、原始逻辑字节分母；`values_only`、`timestamps_only`、`shared_t_controlled`、`whole_object` 互不混用。 |
| R / O | R 额外锁定编码输入、编码 schema 和布局；O 不要求相同编码表示、内部块或方法身份。固定 T/V 时，必须匹配相应支路的完整解析身份；共享 T 受控任务必须固定 T。 |
| 质量与验证 | 位级恢复使用明确的组件和特殊位模式语义；有损 V 从原始域按列核对预先冻结的 max_abs，要求 T 的任务仍须精确恢复 T。锁定验证强度、位置与协议。`artifact_replay` 不能替代匹配的正式资格与该次重放证据。 |
| 资源 | 同一硬件组、物理核与参与线程预算、峰值驻留、实际序列化字节上限及操作期限。外层调度线程与内层团队共享预算，实际后端与参与线程另行观测，**不要求同值**。 |
| 访问与成本 | 同一入口、输入调度、外部分块、原始恢复任务和输出边界；区分方向、计时范围、生命周期、重置、缓存、所有权和字节费用。`pipeline_full` 计外部原始域验证，`pipeline_service` 不计；二者不能同榜。 |
| 留存与恢复 | 每个用例及方法留足独立恢复样本，保留失败证据，冻结依赖闭包政策。该字段是准入条件，不是删除或归档的执行命令。 |

在同一个预算为四核四线程的部署组，实际只用一线程的算法可以和实际用四线程的算法比较，标量与 SIMD
同理。若研究资源预算或 ISA 的影响，应单独声明实验系列和可变维度，不把多个资源预算的数据混成一个榜。
计时采用统一操作边界，不把花费的线程时间相加当作墙钟。请求预算或环境变量本身不证明实际符合预算。

## 原生 stream 与外部 batch 包装

`stream_chunked`、`stream_strict_online` 和 `batch_whole` 是不同合同：

- **有效分块 stream**允许原生和外部有界 batch 包装竞争。同一入口/到达及输出协议下，必须实测缓冲上限、
  首输出和连续输出间隔、背压、finish 恢复全部结果。必须在 finish 前有实际输出，不能整个对象到齐后才处理；
  输入等待、包装缓冲、块压缩、目录及恢复都纳入规定的服务时间与字节范围。
- **严格在线**要求不回放、正式锁定的最坏延迟/状态边界；不把独立块 batch 包装当成严格在线机制。
  **原生限定**还要求服务源为原生。两种要求均不由申请者或插件名称推断。
- `batch_whole` 的完成和状态合同不能伪装成 stream。当前正式流式核验用例及完整服务计量尚未接通；
  这里的 stream 正反例测试验证准入规则，不代表已实测两个实现的流式性能。

## 真实候选切片与正式边界

`m1_lossless_candidate_v2` 在新运行中为六个实际输入、encode/decode 两方向冻结 **12 个 O 轨道合同**。
每个方向同一输入上的 raw-store、Zstd、ALP 用同一比较键；各自的方法、构建与配置身份不变。
计划中用于比较的是冻结后的具体原始对象、逻辑字节、bitwise 验证、整列批访问、进程边界、逐产物
核验和留存下限，不从预期压缩率反推资源限制。报告仅保留开发墙钟，所有候选均 `admitted: false`：
没有正式硬件组、核与 RSS 观测或算法资格。合同 schema 随运行封存，不依赖现场配置复算；旧运行按旧身份复算。

`analysis.comparison.admission_reasons` 只消费**由可信运行验证器生成**且与冻结计划匹配的事实，不从
用户提供的 JSON 加载“已通过”断言。它检查质量/域、资源、时间/字节费用、恢复和验证强度等拒绝条件；
正式运行生成这些事实、计划覆盖/调度闭合、真实运行的稳定性与统计排名仍分别验收。
范围/查询/索引访问等首批其它合同、正式资源与留存执行器、独立 T/V/组合验证仍需后续接通。
