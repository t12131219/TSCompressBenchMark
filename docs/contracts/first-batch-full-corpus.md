## 解析与字节身份

清单按文件显式声明 UTF-8、带表头的物理行、分隔符、小数点、T 格式和缺失策略。V 解析为有限小端 binary64；保留负零、拒绝空字段及非有限文本、十进制溢出和非零下溢。日期标签按声明的语法精确映射到秒坐标，**不**转换为实际 UTC 瞬间；整数 `date` 是原件的有符号 i64 标签，**不**当作 Unix 时间戳。LD 分号文本采用十进制逗号，`exchange_rate.csv` 的斜线分钟格式显式声明。

`weather.csv` 实测有 81 个 `-9999` 源哨兵和一处相邻相同的时间标签。哨兵在此次归档中保留原位模式并单独计数，不得视为有效气象测量，也不在 loader 中自动变成 NaN、零值或插补值。是否允许用于某条路线及其质量、训练合同由后续适用性计划决定。

文件身份使用原件 SHA-256。解析身份由清单中的 parser、角色、类型、形状以及报告中的 loader 与 schema 摘要绑定。对象身份使用 `bmk.dense-axis-and-values-row-major/1`，绑定 T、V 两段的 SHA-256 及列序、语义、dtype 和行数，不依赖路径或格式名。T 是连续的小端 i64，V 是按行交错的小端 f64；此版不生成 nullable 位图，不覆盖原有跨格式 loader 的 NaN 位模式或 NPY 接口，也不更改其对象身份。两段逻辑长度分列，不把源文本字节当数值任务的压缩比分母。

```sh
PYTHONPATH=src /home/fzg/anaconda3/envs/tsbench/bin/python -B -m unittest tests.contracts.test_full_corpus
```

可用 `--manifest <工程相对路径>`，与 `tsbench.api.check_full_corpus(root, manifest, parse=True)` 同一实现。默认清单及首批 scope 强制精确 23 文件闭包；新语料用自己的 scope。不带 `--parse` 时只核验源文件和清单结构/身份关系，**不**复算规范对象。`--parse` 顺序读到 EOF，按不超过 128 行的批次复算全部 SHA-256、分区和轴观测，不落盘全集副本；提前停止迭代不构成源文件的认证。

本次完整复核见 `results/m0-full-corpus-intake-20261119-r1/check.json`。它只证明输入锁和规范身份，不能为任何 codec 宣告适用或跑通。下一门槛是逐文件 × 36 条路线的适用性和实际操作展开，分别绑定 180 项必需义务与 6 项条件义务。先引用已有原生/构建对账，再冻结角色、类型、维度、资源、质量及 fixture 条件；缺适配器或缺新数据证据不能记作不适用，ALP AVX512BW 不能删除，CORAD 历史质量拒绝不能改绿。
